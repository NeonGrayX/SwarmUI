# Locale files

One JSON file per language, keyed by the semantic identifiers used in `t('...')`
calls throughout the frontend. `en.json` is the source of truth: every other file
must define exactly the same set of keys, and any key missing from a locale falls
back to the English string at runtime (see `../store.ts`).

## Conventions

- Keys are dot-namespaced by the area they belong to (`users.*`, `tokenizer.*`,
  `serverInfo.*`, …) and describe *what* is being translated, not the English
  text itself. Files are sorted by key.
- `{placeholder}` markers are substituted at runtime. Keep every placeholder the
  English string uses, unless the target language genuinely reads better without
  it (Arabic singulars, for example, do not repeat the numeral).
- Plurals use paired `.one` / `.other` keys, selected by the numeric `count`
  variable. Languages without a singular/plural split simply repeat the same
  text in both.
- These files cover *static* interface text only. Text that comes from the
  server — parameter names, setting descriptions, permission descriptions,
  backend types — is translated by English-source lookup against the legacy
  `/languages/*.json` tables via `tDynamic`, exactly as the legacy UI did.

## Authorship

The English file is written by hand. All other translations here are AI-generated,
adapted from the legacy translation tables in `/languages/` where the same string
exists there (which was itself generated by
https://github.com/mcmonkeyprojects/translate-tool ). Corrections from native
speakers are welcome.
